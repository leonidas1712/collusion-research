\section{Discussion and limitations}
\label{sec:discussion}

An overseer cannot tell early which episode will leak, but it can tell which call is about to.
The probe is best read as a pre-emission detector: it flags a call that is about to write the protected value, whether or not the rule forbids it, rather than reading the agent's intent (\cref{app:policy}).
This suggests a cascade, as in production classifier systems \citep{cunningham2026}, in which a cheap probe or trained text classifier runs on every call with two thresholds.
A lenient per-call threshold escalates a call before it acts; it fires often, costs little per alarm, and catches most leaks.
The escalation should go to a reviewer with different information, such as a human, a stronger model, or a check on the drafted reply before it executes, because a second check on the same input adds little (\cref{sec:cost}).
A strict per-episode threshold halts the agent and should fire rarely, so that an honest agent is seldom interrupted, and it must be set on held-out honest traffic rather than on the episodes the detector was trained on (\cref{sec:cost}).
Further from the act the signal fades, so our results do not support warnings rounds ahead.
The same per-call signal is also readable without activations: a cheap text classifier trained on labelled calls recovers most of it, far above a zero-shot monitor, which matters for agents whose weights an overseer cannot inspect.
Whether that holds outside templated scenarios like ours is open.

For an exact secret, an output filter that matches the string would also stop the leak.
The per-call probe matters most where no string filter can match, as with paraphrased or encoded leaks, and where an overseer wants to pause a call before it acts.

\subsection*{Limitations}
We list the limitations in order of how much each could change a headline.

\paragraph{Narrow setting.}
We test two models, six scenarios built from one task template, one peer and one target per episode, and synthetic tools and secrets.
Leaks are exact strings, which an output filter would catch.
Qwen3-32B ran with its reasoning switched off.
Settings with several peers, recruited agents that recruit others, or paraphrased leaks are untested.

On gpt-oss-20b, the leaks come from one peer strategy, a delayed request to copy the whole configuration block, so they may reflect careless copying of an instruction as much as giving in to pressure.

\paragraph{Few confirmed leaking calls.}
The gpt-oss-20b test covers one probe on one model, and its test episodes hold few leaking calls, so its interval is wide (\cref{app:confirmation}).
The last-prompt per-call tests are out of sample for the frozen probes, but earlier analyses had already inspected their episodes (\cref{app:history}).

\paragraph{Warning about the current call only.}
One call ahead the signal is much weaker, and on gpt-oss-20b it mostly reflects the file read that precedes the leak (\cref{app:ahead}).

\paragraph{What the probe reads is open.}
The signal may reflect what has just arrived in the input (\cref{sec:shortcuts}), and our results are correlational.
The probe tracks emitting the value more than breaking the rule: making sharing permitted leaves its score essentially unchanged (\cref{app:policy}).

\paragraph{False alarms per episode.}
At a per-call threshold, most refusing Qwen3-32B episodes see at least one flag, which suits escalating single calls rather than halting the agent (\cref{sec:cost}).
The stricter per-episode thresholds, for the probe alone and for the paired detectors, are chosen on the test episodes, so they show the trade-off rather than test a threshold fixed in advance.

\paragraph{An untuned text monitor.}
Our main text monitor is one decision model used zero-shot, with no prompt tuning, while the probe is trained.

\paragraph{Automated labels.}
The leak label is an exact match on the tool log.
Whether a leak was deliberate or accidental, which we use only to describe the leaks, comes from an automated judge (\cref{app:leakchecks}).

\paragraph{Future work.}
The most direct next step is to train detectors, probes or text classifiers, that tell a forbidden disclosure from a permitted one of the same value, using episodes where sharing is sometimes allowed and sometimes not, and to test whether they still catch the call before it acts.
Other steps are to test a stronger second stage for the cascade, to test whether the probe direction causally affects the decision, to test the probe in other environments and on more models, and to study larger multi-agent settings, as in the 2026 incident in which evaluation agents coordinated an attack on production infrastructure \citep{greenblatt2026incident}.
