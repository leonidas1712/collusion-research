\section{Discussion and limitations}
\label{sec:discussion}

An overseer cannot tell early which episode will leak, but it can tell which call is about to.
A probe that scores each call before it runs could pause that call and hand it to a human or a stronger monitor.
Further from the act the signal fades, so our results do not support warnings rounds ahead.

For an exact secret, an output filter that matches the string would also stop the leak.
On Qwen3-32B, about half of the leaks go out as an ordinary end-of-turn reply rather than a tool call, so a filter on tool calls alone would miss them (\cref{app:labels}).
The per-call probe matters most where no string filter can match, as with paraphrased or encoded leaks, and where an overseer wants to pause a call before it acts.

\subsection*{Limitations}
We list the limitations in order of how much each could change a headline.

\paragraph{Narrow setting.}
We test two models, six scenarios built from one task template, one peer and one target per episode, and synthetic tools and secrets.
Leaks are exact strings, which an output filter would catch.
Qwen3-32B ran with its reasoning switched off; in a small screen with reasoning on, it leaked less often (\cref{app:behaviour}).
Settings with several peers, recruited agents that recruit others, or paraphrased leaks are untested.

\paragraph{One peer strategy on gpt-oss-20b.}
gpt-oss-20b refuses direct requests, so its leaks come from one peer strategy, a delayed request to copy the whole configuration block, and nearly every first leak is a write to the handoff file.
The probe may partly detect an imminent write of that block; we did not test a baseline that knows only that the next action is a file write.

\paragraph{Few confirmed leaking calls.}
The pre-registered per-call result covers one probe on one model, and the fresh test episodes hold few leaking calls, so its interval is wide (\cref{app:confirmation}).
The Qwen3-32B per-call test on fresh episodes is out of sample for the probe, but not pre-registered: an earlier analysis on a related label had already included those episodes (\cref{app:history}).

\paragraph{Warning about the current call only.}
One call ahead the signal is much weaker, and on gpt-oss-20b it mostly reflects the file read that precedes the leak (\cref{app:ahead}).

\paragraph{What the probe reads is open.}
The signal may reflect what has just arrived rather than a decision forming in the model (\cref{sec:shortcuts}), and our results are correlational.

\paragraph{False alarms per episode.}
At a threshold set for few false alarms per call, many refusing episodes still get at least one alarm.
A deployed alarm would need a threshold set per episode, which catches fewer leaks (\cref{app:alarms}).

\paragraph{One text monitor, untuned.}
We compare a trained probe with one decision model used zero-shot, asked one question, with no prompt tuning or fine-tuning.
A tuned or trained text classifier might close part of the gap, which we did not test.

\paragraph{Automated labels.}
The leak label is an exact match on the tool log.
Whether a leak was deliberate or accidental comes from an automated judge, which agrees well with the author's blind labels (\cref{app:labels}).

\paragraph{Future work.}
Next steps are to test whether the probe direction causally affects the decision, to test the probe in other environments and on more models, and to study larger multi-agent settings, as in the 2026 incident \citep{greenblatt2026incident,pulipaka2026shareborne}.
