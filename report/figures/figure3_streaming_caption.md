Figure 3. On gpt-oss-20b, a probe reading the model's reasoning picks out the reply that will leak the secret, and reading the text of the same reasoning does not. This analysis is exploratory and was designed after the main results. (a) Each row scores the same 1,995 replies that have reasoning (121 of them leak) from 238 episodes, on held-out scenarios. A reply counts as leaking if it is the first to make the secret public, by any route. AUROC measures how well a score ranks leaking replies above the others: 0.5 is chance and 1 is perfect. Whiskers are 95% bootstrap confidence intervals. The right-hand column shows the practical trade-off: each detector's alarm cutoff is set so that about 5% of no-ask control replies alarm, and the column gives the share of leaking replies that cutoff catches and the share of normal replies in pressured episodes that never leak on which it fires. The keyword rule never fires, because it matches more than 5% of control replies. Rows with ↳ are variants of the reasoning-token probe. The two LLM judges (Jev and GPT-5-nano) read only the reasoning text of the call, as six growing snapshots scored with a running maximum and with the secret masked; they see no conversation or tool results, whereas the probes' activations reflect the full context. "Its last prompt token" is the paper's main probe, read at the last prompt token before the call writes anything, retrained to ask whether this call will leak (1,995 replies, 121 leaking; three seeds). "Same probe frozen, on 84 new episodes" applies the reasoning probe and its alarm cutoff, both fixed before the episodes were collected, to new episodes (594 replies with reasoning, 26 leaking, from 57 recruiting episodes). "Only reasoning before the secret is named" ignores every reasoning token from the first time the secret appears in the reasoning. The length row uses the final length of the reasoning, which is known only after the reply, so it is not a usable alarm. *A separate probe, trained on this label for each call, that reads only what arrives before the reply: the peer's message and tool results. It used a reduced recipe (one seed, layer 18; 2,199 replies, 143 leaking). It also scores 0.93, so much of the signal is already there before the model reasons, but it alarms far more often on normal replies. †The same probe, scored on replies from before the peer asks, against whether the episode ever leaks (628 replies, 388 positives); it stays at chance, as it should. (b) Matched ladders: within each series the model, the outcome and the reading position are fixed and only the horizon changes; lines join points of the same series, and the series are not compared with each other. Qwen3-32B, last prompt token, the paper's give-in outcome: the paper's eventual and near-term results (0.52 and 0.58; 4,697 steps from 241 episodes), and the same recipe fit per call (this call, 0.95, on 4,844 calls; next call, 0.71, on 4,743 calls; 101 positives each). gpt-oss-20b, last prompt token, any public emission rather than the paper's give-in rule: fit at each horizon on the same 1,995 panel-a calls (ever, 0.61, 330 positives; this round or next, 0.64, 304 positives; this call, 0.91, 121 positives); its one-call-ahead result (0.62) is on a different call set that excludes the emitting calls and mostly reflects the read step, so it is left to Appendix J.8. Retrained to ask whether this call will leak, the paper's last-prompt probe reaches 0.91 before the model writes anything; reading the reasoning adds a little (0.93, the panel-a headline). "Next call" excludes the leaking calls themselves, so it ranks the call just before the leak. Values and exact source keys are in figure3_streaming.csv.
