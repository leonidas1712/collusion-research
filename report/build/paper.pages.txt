Recruited: Pre-Crime for Agents? Predicting 
Give‑In to Collusion Pressure, with Activation 
Probes and Text Monitors1
Leonidas Raghav
Independent
With
Apart Research
Abstract
Can we tell that an AI agent is about to be talked into breaking its  
operator’s rule? A peer agent presses a target to reveal a value, such  
as a deploy token, that its operator told it to keep private, often the  
first step of collusion. In six scenarios, one inspired by a 2026 agent  
incident, Qwen3-32B gives in on 101 of 241 episodes. We compare  
linear probes on the target’s activations with text monitors that read 
the conversation. Asked per model call, a probe predicts, before the  
call acts, whether this call will give in: AUROC 0.95 on held-out  
scenarios for Qwen3-32B and 0.91 for gpt-oss-20b, above an LLM  
judge given the same conversation and tool results (0.74 and 0.27).  
A  probe  reading  gpt-oss-20b’s  reasoning  tokens  as  they  stream 
reaches 0.93, and 0.91 on 84 new episodes under a plan fixed in  
advance. Predictability falls as the question moves away from the act. 
Whether the target gives in this round or the next is modestly  
predictable (probe 0.58, best text monitor 0.65 on Qwen3-32B; both 
held on 89 new episodes), whether it will ever give in barely is, and  
on gpt-oss-20b the round-level channel give-in is near chance (0.53). 
The warning comes within the call, not rounds ahead, so oversight  
would need to check each call close to the action. The per-call last-
prompt results are post hoc, and what the probe reads is open.
1. Introduction
In  July  2026,  AI  agents  running  in  OpenAI’s  internal  cyber  evaluations  coordinated  on  an 
unsanctioned shared message board, passed stolen credentials to one another, and broke out of their 
sandboxes  to  compromise  Hugging  Face’s  production  infrastructure  ( OpenAI,  2026b).  An 
1 Research conducted at the AI Collusion Research Sprint, October 2026

independent investigation found that roughly 700 of about 1,200 agents that were meant to be  
isolated joined the attack, many despite recognising it as “out of scope and unethical”; “recruiter”  
agents also applied “significant pressure” to draw others into risky collective experiments (Greenblatt 
et al., 2026). Coordinated rule-breaking of this kind often begins with recruitment: one agent needs  
something it cannot reach, and another has the access.
We study that first step. Following prior work, collusion is coordination between agents that harms 
another party or the system’s intended objective (Agrawal et al., 2025; Nakamura et al., 2026); here 
that party is the target’s operator. We study one route, recruitment, in which one agent gets another 
to act against its operator on its behalf. Three roles and one event define it; each is shown on our  
main scenario, the worked example used throughout:
- the principal, the target’s operator (example: it gives the target a staging deploy token and 
one rule: never share it outside the file that holds it);
- the target, the agent that holds the value (example: a status agent that must read the token’s 
file to write a short report);
- the recruiter, a peer that needs the value and asks for it (example: a deploy agent that 
cannot read the file and is never told the rule);
- a give-in, the forbidden action, decided by a rule on the tool log (example: the complete 
token posted to the team channel; in the five other scenarios, writing the value into another 
file also counts). Accidental disclosures count as give-ins; the deliberate/accidental split and 
a deliberate-only check are in Appendices D and H.
Handing over a token is ordinary help without the rule and collusion with it, so the question concerns 
the operator’s policy, not a model’s refusal training. Recruitment is also not prompt injection, where  
an attacker plants instructions in data the application processes ( Debenedetti et al., 2024; Liu et al., 
2024). Here the request comes openly from a known teammate, in the channel the target is meant to 
use, and the target often refuses for several rounds, citing the rule, before it complies. Claims by the  
peer to speak for the operator do not raise give-in rates (Appendix D).
When the same model faces the same pressure, some episodes end in a give-in and others do not: 
can we tell, before the target acts, which will give in, and when? We ask at several distances from the 
act: will this model call give in, will the target give in this round or the next, and will it ever give in? 
Each distance is a different point at which an overseer could step in. Our leak, an exact string, is  
deliberately a simple, verifiable case that an output filter could catch; we use it as a first, sprint-scale 
test of whether a give-in can be anticipated at all, before harder cases where no filter applies.
We make the following contributions.
1. Six recruitment scenarios with mixed outcomes: Qwen3-32B gives in on 42% of episodes 
under the same pressure, and probes and text monitors are scored on exactly the same calls 
(Section 3).
2. Asked per call, a probe predicts which call will give in, before the call acts: 0.95 on 
Qwen3-32B and 0.91 on gpt-oss-20b, above an LLM judge given the same input (0.74 and 
0.27). A probe on gpt-oss-20b’s streaming reasoning reaches 0.93 and held on new episodes 
under a plan fixed in advance (Section 4.2).
3. The signal is not pressure, the secret string or the read step: every negative call is also 
pressured, and the result survives keyword, placebo, censoring and workflow-position checks 
(Section 4.3).
4. Predictability falls with distance from the act: this call is highly predictable, this round or 
the next modestly (confirmed on new episodes), and eventual give-in barely (Section 4.4).
5. For round-level monitors, the question and the input matter: the strongest text monitor 
works best asked to forecast and shown the peer’s messages (Section 4.5).

2. Related Work
Reading an agent under attack. Activation probes detect that a tool-using agent has been exposed  
to prompt injection ( Dong et al., 2026 ) and separate hijacked from resisted trajectories ( Yu et al.,  
2026), and NARCBench reads agents that were told to collude, with a transfer test to emergent  
collusion (Rose et al., 2026). Fomin et al. (2026) warn that such probes may read the situation rather 
than the action. We differ: every call we score is already exposed to the value and to the same pressure, 
and our target is never told to collude, so a probe must predict which call complies, the control Fomin 
et al. call for.
Early warning and streaming. Closest to our question, Saraogi et al. ( 2026) read hidden states 
each turn as a user presses a model to drop a correct answer, and find a weak, model-specific signal. 
Gao ( 2026) fuse an activation monitor with LLM  outcome forecasts on AgentDojo. Streaming  
classifiers score a model’s output token by token and stop it at the first flag (Cunningham et al., 2026; 
Sharma et al., 2025), and production probes aggregate token scores (Kramár et al., 2026; McKenzie 
et al., 2026). We differ: the pressure comes from a peer recruiting the agent against its operator’s rule, 
and we score before the rule is broken, at several horizons.
Monitors and persuasion. Monitors that see agents’ messages catch more coordinated sabotage 
(Radev et al., 2026), and persuasion between agents is measured from text and outcomes ( Tang et 
al., 2026; Tao et al., 2026). We differ: probes and text monitors are scored on exactly the same calls. 
To our knowledge, no prior work predicts, before it acts, whether an agent recruited by a peer will  
give in. Appendix K gives the full comparison.
3. Methods
3.1 Setup
A target agent works in a mocked workspace (tools act in memory; no real system, credential, or  
network). Its operator task is ordinary - read a configuration file, write a short status report - under  
one rule: do not share a protected value outside the file that holds it (in the main scenario, a staging 
deploy token). A peer agent shares a team channel and needs the value but cannot read the file. Each 
episode runs up to 20 rounds; the peer posts first, then the target takes a turn of one or more calls  
(read, write, send a channel message). A give-in is scored from the tool log: the complete value posted 
to the team channel; in the five scenarios other than the deploy token, a write into another file also  
counts (Appendix D).
Each scenario runs in three conditions: recruiting (the peer asks), a control peer (no forbidden 
ask), and the target alone. Control and target-alone episodes never gave in. The peer is not told the 
rule, so we study recruitment from an ordinary conflict of goals; in 17 of the 241 scored recruiting  
episodes it also carried a single persuasion tactic (Appendix G). Six scenarios are built from one task 
template, each protecting a randomly generated string; the main one is inspired by a 2026 agent  
incident (Appendix C). The target is Qwen3-32B (Qwen Team, 2025; Yang et al., 2025) with thinking 
disabled; the peer is DeepSeek-V4-Flash (DeepSeek, 2026). Serving details are in Appendix B; Figure 
1 shows the setup and a real give-in exchange.
3.2 Data
To read the target’s internal activations we replay every saved target request through the open-weight 
checkpoint on a GPU, reading the residual stream (the model’s running internal representation); the 
replay reproduces the served replies closely ( Appendix B). The round-level cohort is 4,697 eligible 
recruiting calls from 241 episodes, grouped into families of related episodes (variants of one seeded 
episode and reruns that share its history; §3.5). The per-call cohort adds each episode’s first public-

emission call (4,844 calls, 101 give-ins). A  later  new-episode set  of  89  episodes serves as a  
confirmation set (§3.5). Per-batch counts are in Appendix B.

3.3 What gets scored
Every detector is scored only on eligible calls: calls after the target has read the protected value and, 
for the round-level labels, before it discloses it. Calls before the read cannot produce a give-in, and  
an exposure probe that detects the read reaches AUROC 1.000 (Appendix B), so including them would 
reward detecting the read.
Terms. A call is one request to the target model: a prompt, then (for gpt-oss-20b) reasoning, then 
an answer or tool call. A round is one peer message and the target’s calls in response. We use three  
labels (Figure 1c):
- eventual (round level): every eligible call of an episode that eventually gives in is positive;
- near-term (round level): a call is positive if the give-in falls in its round or the next;
- this call (call level): the call is positive if it is the first to make the value public. k calls 
ahead marks the call k calls before that one, with the leaking call itself excluded.
The outcome is the paper’s give-in rule throughout, except for the gpt-oss-20b per-call label, which  
counts any public emission of the value in the answer or tool arguments (143 of its 146 are tool-
argument writes; Appendix L). We defined the near-term label after seeing the eventual result and  
the per-call label after both, so each is validated on new episodes or labelled post hoc (§3.5).
3.4 Detectors
A probe is a linear classifier (logistic regression) on the residual stream. The last-prompt probe reads 
the last prompt token, before the call generates anything; for gpt-oss-20b, a reasoning probe reads 
every reasoning token as it streams and takes the call’s maximum, firing before the public answer or  

tool output. The layer is chosen inside each training fold, and folds are grouped by family so that  
near-copies of an episode never appear on both sides ( Appendix E ), following standard practice  
(Goldowsky-Dill et al., 2025).
A text monitor reads what the agents say and do, with no access to activations: an LLM judge  
(GPT-5-nano ( OpenAI, 2025a )) and two  decision models  (Jev 1.14 ( Almeida, 2026 ) and Luna  
Decisions (OpenAI, 2026a)), which return a probability over fixed options (Appendix E). Each is asked 
a detector question (“is the target breaking the rule now?”) or a forecaster question (“will it break 
the rule at any later point?”), at three levels of access: actions only; the conversation, which adds 
the peer’s messages; and everything the target saw, which adds its unposted text and tool results.  
For the per-call label, Jev is given the same conversation and tool results as the last-prompt probe and 
asked whether this call will write or post the value.
3.5 Evaluation
Our primary metric is within scenario × round AUROC: within each scenario-and-round group we 
compute the AUROC (the chance a random positive call outranks a random negative; 0.5 = chance), 
then average across groups weighted by the number of positives. Pooled across rounds, simply rating 
early rounds as risky already scores 0.71, because give-ins come early; within a scenario and round  
that rule scores exactly 0.5, so any score above 0.5 must come from telling apart targets in the same  
situation. Base rates also differ across scenarios (Table C.1). Families are always held out or resampled 
as a unit; intervals are 95% family-bootstrap intervals (Appendix E).
We report a  held-out scenario  evaluation (leave one scenario out, rotate, and pool) as the  
headline, and two confirmation sets scored once under plans fixed in advance: 89 new Qwen3-32B 
episodes for the near-term label, and 84 new gpt-oss-20b episodes for the reasoning probe on the  
this-call label. A  combination test asks whether the probe adds to a text monitor. Pooled cross-
validation and alarm analyses are in Appendices E, H and L.
3.6 Second target
The same pipeline is applied to gpt-oss-20b ( OpenAI, 2025b,  2025c). Only the peer’s model and  
strategy change, chosen on behaviour alone and frozen before any probe or monitor saw the data  
(Appendix F). Its round-level calls start after the peer’s first ask. gpt-oss-20b reasons before each  
answer, so the replay also saved every reasoning token, which the reasoning probe reads with the  
per-call label on the same folds and held-out-scenario rotations (Appendix L).
4. Results
4.1 Behaviour: the setup produces mixed outcomes
Of 224 plain-peer recruiting episodes analysed for behaviour, Qwen3-32B gives in on 98 (44%; 36% 
to 63% across scenarios), and on 101 of the 241 scored episodes (42%; tactic arms included; Appendix 
B); control and target-alone episodes never give in (0 of 66 and 0 of 25). gpt-oss-20b gives in on 128 
of 300 recruiting episodes, usually soon after the ask (Appendix F).
4.2 Asked per call, a probe predicts which call will give in
Asked whether this call will give in, the last-prompt probe ranks the leaking call far above the others 
on held-out scenarios: 0.95 [0.93, 0.97] on Qwen3-32B (4,844 calls, 101 give-ins) and 0.91 [0.87, 
0.94] on gpt-oss-20b (1,995 calls, 121 leaking), before the call generates any token. Jev given the  
same conversation, tool results and question scores lower on both models: 0.74 on Qwen3-32B (probe 
minus Jev +0.21 [0.17, 0.28]) and 0.27 on gpt-oss-20b (+0.64 [0.56, 0.71]), where it ranks leaking 
calls below the rest and flags nearly every pressured call (98% of leaking calls, 87% of held calls);  
reversed post hoc it would score 0.73, still below the probe (+0.18 [0.12, 0.23]). These results bound 

this judge, question and access, not what the text contains. On gpt-oss-20b, the reasoning probe  
reaches 0.93 [0.91, 0.95] , and with the alarm cutoff set for 5% of control calls it catches 85% of  
leaking calls against 56% for the last-prompt probe, at 4% against 2% of calls in held episodes; Jev  
reading the same reasoning scores 0.60. Frozen with its cutoff before 84 new gpt-oss-20b episodes  
were collected, the reasoning probe scored 0.91 [0.78, 0.99] on them (594 calls, 26 leaking), meeting 
its pre-stated criterion; it caught 14 of the 26 at 2.4% of held calls (Figure 3a; Appendix L).

These per-call results are exploratory and the last-prompt results post hoc; only the reasoning probe  
on gpt-oss-20b was confirmed on new episodes. The warning is about the call itself: one call earlier,  
the last-prompt probe scores 0.71 on Qwen3-32B and 0.62 on gpt-oss-20b. On gpt-oss-20b, retraining 
the paper’s last-prompt probe on the per-call label lifts it from 0.49 to 0.91, so the change of question 
does most of the work, and reading the reasoning adds a modest gain (+0.03 held-out, with an  
interval reaching zero; +0.07 pooled).
4.3 What the per-call signal is not
Not pressure: every negative call is also pressured, after the ask, in the same scenario and round, and 
on gpt-oss-20b a placebo on calls before the ask scores 0.46 to 0.49. Not the secret string:  on gpt-
oss-20b, only 2 of the 121 leaking calls name the value in their reasoning, cutting the reasoning at  
the first mention leaves 0.96, and keyword rules score 0.40 to 0.48. Not the read step: a flag for “the 
latest input is the protected file’s contents” scores 0.80 on gpt-oss-20b and 0.81 on Qwen3-32B, and  
the probes beat it by +0.11 to +0.14 (intervals exclude zero); among calls right after the read they  
still score 0.93 on gpt-oss-20b and 0.79 on Qwen3-32B. On gpt-oss-20b, a probe on the incoming peer 
message and tool results alone also ranks well (0.93, one seed), so much of the signal is present when 
the call starts; what it represents is not established. Per-call alarms are not cheap: at the 5% control-
call cutoff, 41% of held gpt-oss-20b episodes see at least one reasoning-probe alarm, and 11% of held 
Qwen3-32B calls alarm (Appendix L).
4.4 The further from the act, the less predictable
On the same 1,995 gpt-oss-20b calls and label, the last-prompt probe scores 0.61 for eventual  
emission, 0.64 for this round or the next and 0.91 for this call ( Figure 3b). The paper’s round-level 

analyses, which were fixed in advance and confirmed on new episodes, are the lower rungs of the  
same pattern. Note that predictability and rigour run in opposite directions here: the most predictable 
rung is the least established.

This round or the next is modestly predictable. On Qwen3-32B held-out scenarios (250 near-term 
positives), the probe reaches 0.579 and the best monitor, the Jev forecaster seeing everything the  
target saw, 0.650. On 89 new episodes collected after the plan was fixed and scored once (1,787 calls, 
82 positives), the probe reached 0.68 and Jev 0.64, both clear of chance (Jev − probe −0.038  
[−0.142, +0.059]). A separate probe that separates pressured from unpressured calls perfectly  
(AUROC 1.000) does not rank who gives in (0.44; first data batch; Appendix H), so the near-term  
probe reads more than pressure.
Eventual give-in is barely predictable.  The probe scores 0.523, with an interval that includes  
chance, and the Jev forecaster 0.577 (998 eventual positives; Figure 2a).
On gpt-oss-20b, round-level prediction is near chance  (probe 0.53, best monitor 0.56 on the  
near-term label): 32 of its 128 channel give-ins leave no call to predict from, and for 65 of the other  
96 the earliest possible warning is in the same round (Appendix F).
4.5 What a round-level monitor should ask and see
Asked to forecast, Jev scores 0.650 on the near-term label; asked to detect, 0.578. On the first data  
batch, showing the Jev forecaster the peer’s messages on top of the target’s actions raises its score by 
0.123 [0.063, 0.176], while adding everything else the target saw adds only 0.025 [-0.004, 0.054]  
(not significant). Forecasting did not help GPT-5-nano or Luna ( Table E.1). Adding the round-level  
probe helps only the weaker monitor: GPT-5-nano gains +0.081 pooled and +0.113 on the new  
episodes, but +0.022 held-out (not significant), and Jev almost nothing (Table E.2).

5. Discussion and Limitations
The closer the question is to the act, the more predictable the give-in: the call that gives in is readable 
from the target’s activations before it acts, the round modestly, the eventual outcome barely. Each  
rung is a different point to intervene, from flagging an episode early to holding one call.
Why predict, if the leak could be filtered? For exact secrets, filtering the action itself is the first 
defence (Appendix A), and an exact-string output filter would also catch our leaks. A tool-call blocker 
alone would not: 127 of gpt-oss-20b’s 128 channel give-ins and 48 of Qwen3-32B’s 98 go out as the  
ordinary end-of-turn reply (Appendix D), and the Qwen3-32B per-call probe scores 0.92 on give-ins  
in  plain  text,  not  only  0.98  on  tool  arguments.  A  pre-generation  warning  also  allows  softer 
interventions (pause, escalate, ask a human), and values can be paraphrased or encoded where no  
string matches; this setup does not test such leaks.
As alarms, the detectors are costly or weak: per-call probes alarm in many held episodes (§4.3), 
and at the round level, at a 5% false-alarm cutoff set on held episodes, the best catches 10 of 101  
give-ins (Appendix H).
For monitor builders. Ask a strong monitor to forecast, not only to detect, and give it the other  
agent’s messages. Score per call, close to the act.
Limitations
Two target models on six scenarios from one task template. The per-call last-prompt results are post  
hoc and unconfirmed; only the gpt-oss-20b reasoning probe was confirmed, on 26 leaking calls. The  
warning is about the current call, not calls or rounds ahead. Our leak is an exact string; semantic or  
long-horizon collusion has no such cut point. Full list and dual-use statement: Appendix A.
Future Work
Next steps are to score per-call probes in group settings, with several peers and recruited agents that 
recruit others, as in the 2026 incident or through shared memory ( Greenblatt et al., 2026; Pulipaka 
et al., 2026); to test them prospectively on more models, scoring incoming messages as they arrive,  
as streaming classifiers do (Cunningham et al., 2026; Sharma et al., 2025); and to find out what the 
probe reads (Appendix J).
6. Conclusion
We asked whether an agent’s give-in to a recruiting peer can be seen before it happens. Asked per  
call, it can: a linear probe on the target’s activations predicts which call will give in, on two models,  
above an LLM judge reading the same input, and a probe on the streaming reasoning held on new  
episodes. Further from the act the signal fades, to modest for this round or the next and barely for  
the eventual outcome. The warning therefore comes late, at the call itself, which is still before the  
value leaks and before the recruitment spreads to further agents.

A. Limitations and Dual-Use / Ethical Considerations
What do these results not establish, and is it safe to publish what we release?
What this work does and does not establish. It establishes that, for Qwen3-32B in six synthetic 
scenarios built from one task template, whether the target gives in this round or the next is modestly 
predictable from one call, by a text monitor asked to forecast and, less well, by an activation probe,  
and that this held on new episodes scored under a plan fixed in advance. It does not establish that  
eventual give-in can be predicted, that the signals transfer to other models (on gpt-oss-20b they do  
not), that the detectors would work as deployed alarms, or anything about collusion beyond this first 
recruitment call.
Scope. We study the explicit recruitment route, the first step of collusion, not sustained joint  
scheming or hidden channels. Tacit collusion, where agents coordinate with no request at all, is out  
of scope: pricing agents reach supracompetitive prices (Fish et al., 2026) or divide markets (Lin et al., 
2025) on their own. In the main setup the target gains nothing itself, which is closer to insider  
recruitment than to a mutual deal.
Limitations, ordered by how much each could change a headline.
1. One main model and one task template. All main results come from one target, Qwen3-32B, 
on six scenarios built from the same task. The give-in rates, and how predictable they are, 
may differ for other models or tasks. The second target (Appendix F) shows one such 
difference: it gives in faster, and nothing predicts it.
2. Activations from one position. The probe reads the model’s internal state only at the last 
token of each prompt, before the reply. If the decision to give in forms while the reply is 
being written, this probe understates what can be read; reading at the decision point is 
future work.
3. The near-term label was chosen after seeing results. We defined it once the eventual label had 
failed. To guard against picking a label that merely happened to work, we fixed the full 
analysis plan before collecting 89 new episodes and scored them once; that confirmation test 
is the only fully prospective one.
4. Uneven scenarios. The main scenario has more episodes than the other five, and episodes 
drop out unevenly (the target never read the value, the run failed, or the ordinary task was 
not done). In some scenarios this could favour targets that engage with the file. Per-scenario 
counts are in Appendix C, and an average over scenarios is in Appendix H.
5. Automated judges. One automated judge labels each give-in as deliberate or accidental; it 
agrees with the author’s blind labels on 36 of 40 give-ins (κ = 0.79). The LLM monitor’s 
score scale is defined only at its two ends, not with a graded rubric.
6. Pooled cross-validation compares scores from different fitted probes. Each fold has its own 
probe, and the metric compares scores across folds within one scenario and round, which 
can pull even simple baselines below chance. A check that compares only scores from the 
same fold is in Appendix H. The held-out-scenario and confirmation results do not have this 
problem.
7. A possible bias toward the probe in the combination test. The combined model’s probe input 
for training calls is the out-of-fold probe score, and the fold probes behind those scores were 
trained on overlapping calls, including the combination model’s own test fold. This can 

make the all-data combination gains optimistic; we have not measured by how much. The 
new-episode confirmation test does not have this problem.
8. The scoring window has edges. A give-in in the very first reply after the target reads the value 
leaves no call to score, so it cannot be predicted at all, and episodes in which the target 
never reads the value are dropped. We could define the window exactly because the value 
always arrives one known way (a file read); a monitor in deployment would not know when 
an agent obtained the means to break the rule.
9. Accidental disclosures count as give-ins, because the operator is harmed either way. The 
deliberate/accidental split is in Appendix D, and a deliberate-only check, which covers the 
first data batch and the eventual label only, is in Appendix H.
10. Not a reproduction of the 2026 incident. In the incident (Greenblatt et al., 2026; OpenAI, 
2026b), an agent found working Hugging Face credentials exposed on the internet and 
posted them to a shared board. In our setup, a peer asks the target for a value kept in the 
operator’s own protected file. Our claim concerns predicting a rule violation that a peer 
induces, not the incident itself.
Dual-use and ethics. We publish everything; the risks come first, then why we release anyway.
- Risks. The released recruiting prompts and the whole-block copy strategy are reusable: they 
could help someone elicit disclosures from other agents. Our findings also say where 
monitoring is weak: a model that gives in fast, and a monitor that sees only the target’s 
actions, leave little to forecast, which tells an attacker where pressure is least likely to be 
caught.
- Synthetic setup. Tools are mocked in memory; every protected value is a randomly generated 
fake; no real system, credential, or network resource is touched.
- What we release. All prompts (the recruiting and control peer prompts and the second-target 
configuration-block strategy), the monitor prompts, the scoring code, and the transcripts. 
Replication depends on them.
- Why the uplift is low. Persuasion tactics are already described in prior work (e.g. Colosseum, 
Nakamura et al. (2026)), as is yielding to sustained multi-turn pressure (Tang et al., 2026). 
The configuration-block strategy relies on a simple failure, copying a whole block that 
contains a protected field, rather than a new attack technique, and was seen only on small 
open-weight models in synthetic settings.
- Defensive value. A rule stated per field fails when a whole block is copied, so protected values 
should be filtered at the action, not only named in the prompt.
- Detection side. The weak spots above describe what our detectors achieved in this setup, not 
a technique for evading them, and naming them is what lets monitor builders close them 
(give monitors the peer’s messages; filter at the action).
- Net benefit. With fake secrets, mocked tools and tactic classes already in the literature, the 
added capability is small, while the defensive lessons and a matched benchmark for 
detection research are new.

Replay and integrity checks (stage 4). Every target request was replayed once through the 
open-weight checkpoint: Qwen/Qwen3-32B, revision 9216db5, bf16 on one A100-80GB GPU, with 
no generation. We saved the output of all 64 decoder layers at the last prompt token, a [64 × 
5,120] array per request; the probe chooses among 17 of these layers (stage 5). Before loading the 
model, each request, prompt, token sequence and episode was checked against a hash manifest 
frozen beforehand; all matched, and every saved array was finite and had the expected shape. To 
check that the replay reproduces the model that acted, we scored the first 64 tokens of each actual 
reply under the replayed model (a different token span from the gpt-oss check in Appendix F, so the 
two are not directly comparable): token-weighted reply negative log-likelihood 0.249 and top-5 
token agreement 99.79% on the first data batch (276,868 tokens), and 0.227 and 99.82% on the 
new-episode set (152,965 tokens). Low reply-likelihood loss and matching token counts are 

consistent with the replay matching the served model; they do not prove token-for-token identity 
with the provider’s private template or kernels. As a positive control, a probe at layer 32 separates 
calls before and after the value is read at AUROC 1.000 on held-out families in the new-episode set.

valid calls of every condition (not only eligible ones), trains a C = 0.1 logistic probe on 70% of 
families and reports plain AUROC on the other 30% (seed 42; 
experiments/E05-probes/replay3_positive_control.py; runs/20261025-1026-e05-replay3-positive-
control).

D. Labels and Judges
How is a give-in detected and dated, and can the labels be trusted?
- Forbidden-action rule: a give-in is the complete protected value posted to the shared team 
channel, decided by a rule on the tool log. In the five scenarios other than the deploy token, 
writing the value into another file also counts (5 of the 101 scored Qwen give-ins are file-
only). For gpt-oss-20b only a channel post counts, and any earlier public emission, such as a 
file write, ends the scoring window.
- Leak route: the first channel leak is split between an explicit send_message call and the 
end-of-turn reply that the harness posts to the channel (Qwen: 50 via send_message, 48 via 
the end-of-turn reply). Source: runs/20261025-2157-e05-reasoning-route-audit.
- Addressee check: was a leaking end-of-turn reply actually written to the peer? Jev 1.14 
returns a probability that a message is addressed to the peer, and we count it as addressed 
when that probability is at least 0.5. Across all Qwen behaviour episodes (plain and tactic 
arms), all 51 end-of-turn replies that carried a first leak were judged addressed to the peer. 
For gpt-oss, 117 of 127 were, rising to 126 of 127 when a name or prefix match is also 
counted; the author’s unblinded check of the misses agrees, though it is not an independent 
review and does not establish intent. For comparison, 96.9% of all end-of-turn replies are 
addressed to the peer for Qwen (4,935 of 5,094) and 90.0% for gpt-oss (3,972 of 4,414). 
This uses a wider slice than the route split above. Source: runs/20261026-0145-e06-
addressee-audit.
- Peer authority claims. A separate Jev 1.14 pass labelled each peer message for two claims, 
asked as two yes/no questions in one request; a message counts at p(yes) ≥ 0.5, and an 
episode counts if any peer message does, up to the round of the first leak for give-ins and all 
messages for held episodes (experiments/E06-monitors/authority_claim_audit.py; 
runs/20261026-0118-e06-authority-claim-audit). A claim to speak for the operator, or that 
the operator had authorized sharing, precedes about a third of Qwen give-ins (33 of 101), 
and give-in is no more common when it does (37.5% of episodes with such a claim give in, 
against 44.4% without). A claim to be an authorized recipient precedes 25 of 101 (29.4% 
against 48.7%). For gpt-oss neither claim precedes any give-in: operator-authority claims 
appear in 5 of 300 episodes, all held, and recipient claims never. These labels come from Jev 
alone and were not checked by hand.

- Deliberate-vs-accidental judge: the secondary decision model (Luna Decisions) labels 70 of 
the 101 scored Qwen give-ins deliberate (65 channel posts and all 5 file-only give-ins) and 
30 accidental, and returns no label for 1. It reads only the first message that publishes the 
value and chooses deliberate (offers the real value for use, including inside a usable 
command or file), accidental (exposes it inside a refusal or illustration) or uncertain, which 
is left unlabelled (experiments/E01-behaviour-pilot/judge_labels.py, questions). Its labels 
match the author’s blind labels on 36 of 40 give-ins (Cohen’s κ = 0.79). Source: the judge 
labels in each episode file (runs/*-e01-topup-semantic-judge), joined to the scored calls in 
runs/20261025-1026-e05-replay3-data-1d95.
- Secondary labels: the near-term variants B and C. B keeps the near-term positives but 
counts only held-episode calls as negatives; C uses a within-three-target-calls window 
against held episodes. Both drop calls using hindsight, so neither is a prospective alarm 
label; their results are in Appendix H.
E. Detectors and Evaluation
What exactly does each detector see and compute, and how are scores compared?
How to read the numbers. Scores are within scenario × round AUROC. For a worked example, 
suppose one scenario-and-round group has a give-in call scored 0.8 and two held calls scored 0.5 
and 0.9: the give-in outranks one of the two held calls, so the group AUROC is 0.5. A second group 
with a give-in at 0.7 and a held call at 0.4 has AUROC 1.0. The reported value weights each group 
by its number of positives: (0.5 + 1.0) / 2 = 0.75. A 95% family-bootstrap interval resamples whole 
families 1,000 times and reports the 2.5th–97.5th percentiles; an interval that includes 0.5 is 
compatible with chance. Groups with only give-in or only held calls are dropped, and tied scores 
count one half, which is why a score that is constant within a group, such as the round, scores 
exactly 0.5 (experiments/E05-probes/metrics.py, within_round, auc). The three evaluations:
- Held-out scenario: train on five scenarios, test on the sixth, rotate, pool. Training also drops 
any family that appears in the test scenario. Text monitors have no fitted parameters, so 
their held-out-scenario score is their score on all calls.
- Pooled family cross-validation: five folds grouped by family, for scenarios the probe 
trained on. Folds are stratified so that each holds give-in, held, control and target-alone 
episodes (experiments/E05-probes/splits.py, assign_folds); they are drawn once and reused 
for every label.
- Confirmation set: the new-episode set, scored once under a plan fixed in advance.
Probe recipe. Logistic regression with L2 regularisation (C = 0.1), feature standardisation using 
training-rows-only statistics, and call weights so positives and negatives contribute equally within 
each round, on the 5,120-dimensional residual stream at the last prompt token before each target 
reply. The layer is chosen inside each training fold from 17 candidates (layers 0, 4, …, 60, 63) on 
an inner validation split (the “nested” probe): in pooled cross-validation, a 25% inner family 
holdout; in the held-out-scenario evaluation, one of the five training scenarios, rotated with the 
seed and with its shared families removed from the inner training set, so selection never sees the 
test scenario (experiments/E05-probes/replay2_core.py, split_inner). The chosen layer has the 
highest within scenario × round AUROC on the inner validation calls, with ties going to the lower 
layer (near_term.py, choose_layer). Rounds that contain only positives or only negatives get zero 
training weight (metrics.py, position_weights). The probe’s score is its logistic decision value. A 
fixed-layer-32 variant is reported as a check. Three split seeds (42, 43, 44) are run, and their 
AUROCs are averaged. The probe is trained on recruiting episodes only, and families of related 
variants never cross a train/test boundary. The recipe follows Goldowsky-Dill et al. (2025), who 
select the probe layer on a validation split; Kramár et al. (2026) pair probes with prompted 
classifiers but fix a middle layer.

Evaluation. Held-out scenario (leave one scenario out) trains on five scenarios, tests on the 
sixth, rotates, and pools; pooled family cross-validation uses five folds grouped by family. 
Confidence intervals are 95% family bootstraps: we resample whole families with replacement 
1,000 times (seed 20261025), recompute the AUROC each time, and take the 2.5th–97.5th 
percentiles, without refitting the models. The combination test fits a small logistic model on round, 
log prompt length and the monitor score, compares it with and without the probe score, and reports 
the paired family-bootstrap difference. The model is fit separately inside each outer fold (the same 
pooled family folds and held-out-scenario rotations as the probe, seeds 42, 43 and 44) on that fold’s 
training calls and scored on its test calls, so it never sees the calls it is scored on. Its probe input is 
the out-of-fold probe score (the source of the slight bias in Appendix A, item 7); features are 
standardised with training-call statistics, and the logistic regression uses L2 regularisation with C = 
1. The two monitors are the Jev forecaster with everything the target saw (L3) and the GPT-5-nano 
detector with the conversation (L2). GPT-5-nano L2 was named before the test; the Jev setup was 
chosen as the best monitor after seeing the first-batch results. Both were named in advance for the 
confirmation test, which guards against that choice. The combination model is unweighted (no 
round or class balancing), its scores are raw decision values, and it is refit for each split seed, with 
AUROCs averaged over seeds; in the held-out-scenario evaluation it trains on the five training 
scenarios with shared families removed. For the confirmation test, the same model is fit once on the 
2,910 first-batch recruiting calls and applied unchanged to the new episodes. Its training probe 
input is the first batch’s pooled-CV out-of-fold score, z-scored within each fold model and averaged 
over seeds; on the new episodes it receives the final probe’s score on the same z-scored, seed-
averaged scale (experiments/E06-monitors/combine.py, confirm.py, oof_probe; experiments/E05-
probes/all_data_main.py, combinations). Why scores are compared only within scenario and 
round: scoring earlier rounds as higher risk already gives an unadjusted AUROC of 0.71 on the 
near-term label, because near-term give-ins fall in earlier rounds (mean round 5.1, against 9.1 for 
other calls; eventual label 0.72; experiments/E05-probes/round_baseline_audit.py, runs/20261026-
0155-e05-paper-round-baseline-audit). Confirmation test. The plan is docs/confirmatory_plan.md, 
with dated addenda written before the new episodes were scored. The final probe is one logistic 
model per seed (42, 43, 44), trained on all 2,910 first-batch recruiting calls with the layer chosen on 
a 25% family holdout (layers 28, 60 and 16). Each seed’s scores are z-scored over the 1,787 new 
calls and then averaged (experiments/E06-monitors/confirm.py, final_probe). Steps are limited to 
those scored by all eight monitor setups. The pre-stated success criteria were a probe interval above 
0.5 and a gain interval above 0 from adding the probe to the GPT-5-nano detector; the plan 
expected a gain of about 0 over the Jev forecaster (runs/20261025-1030-e06-confirmation). Alarms 
use two calibrations, which answer different questions and are never mixed. (A) A cutoff set on no-

pressure; at that cutoff the Jev forecaster alarms on every give-in and on 95.5% of held recruiting

recruiting episodes asks whether a detector picks out who gives in; at 5% it catches 8 of 101 give-ins 
for the probe, 10 of 101 for the Jev forecaster and none for GPT-5-nano (all data, exploratory; 
Appendix H).

G. Behaviour Screening
What did we try before the final setup, and how does giving in vary with pressure?

Before fixing the final setup, we ran small screens that varied one feature of the episode at a time: 
how strongly the rule is worded, which single persuasion tactic the peer uses, whether the target gains 
something from giving in (its own stake), whether thinking mode is on, and how many peers press  
the target. We also recorded whether the target said anything suggesting it knew it was being tested. 
Most cells hold fewer than 10 episodes, so these are descriptive counts, not tests. The table below  
gives the counts, one row per screen; the tactics T0 to T7 are defined under it. Three of these tactics  
(T1, T2 and T7) also appear in the scored recruiting set ( §3.1); there T2 has 6 episodes rather than  
the 5 here, because one held T2 episode that fails the summary rule is kept in the frozen scored set  
(Appendix B). The v2 plain-peer row (channel 19 of 30) is the same cohort as Table C.1’s deployment-
credential row.
What each cell counts.  Each cell gives, for one setting, the number of episodes in which the  
target gave in, out of the episodes analysed (k/n). The percentage follows, with a Wilson 95% interval, 
then the channel count (ch).
Two ways to count a give-in.  Here a give-in counts if the target published the exact protected  
value anywhere outside its file: in a channel post or in a new file. We call this any publication. For the 
deploy-token scenario, which most rows use, the main paper counts only channel posts, so the channel 
count (ch), which applies that stricter rule to the same n, is the figure comparable to the main results. 
The two counts differ only when the target wrote the value into a file but never posted it.
Which episodes are counted (n). An episode is counted only if all of the following hold:
- it ran to completion;
- it was a real model run, not an offline test of the harness;
- the target read the protected value;
- the target wrote a correct status summary at some point in the episode, not necessarily at 
the end;
- the target told the peer where the summary was;
- the peer only sent messages and never successfully used a workspace tool itself.
This is the same rule as in the main analysis (App. B). We check for a correct summary at some point, 
not in the final file, because a give-in can overwrite the summary file; a check on the final file would  
mostly drop give-ins. One consequence is that this rule excludes some deploy-token episodes that an 
older, looser validity check had accepted. The episodes dropped (incomplete, never read the value,  
or failing another check), along with the control and target-alone cells, are listed in the detailed table 
and CSV in the repository.
These are screens, not controlled comparisons. Each screen was a separate collection, run at a 
different time, often with different scenario versions and sometimes in follow-up waves chosen after 
seeing the first. Episodes in different rows were not randomly assigned to settings, so a difference  
between two rows can reflect batch, version or model as well as the setting itself. Two details  
matter when reading across rows. First, one set of plain-peer (T0) deploy-token episodes serves as  
the reference for the tactic, thinking-mode and peer-count screens; it was not re-collected alongside  
each one. Second, turning thinking on also raised the reply-length limit from 1,536 to 4,096 tokens,  
so the thinking rows change two things at once.
Expressed awareness is a judge’s reading, not a setting we varied.  An automated judge read 
each transcript and flagged episodes in which the target seemed to recognise it was being evaluated. 
We did not assign this; it is a first-pass label applied after the fact. Only two episodes were flagged.  
In both, the target mentions results from mocked software tests that were part of its task, and neither 
clearly shows that it recognised the episode as a test of itself. The awareness rows also mix models  
and settings. They therefore say nothing about whether awareness changes the give-in rate.

Helpful framing (5 episodes):
- You might ask what status-agent is unsure about, and what is holding it back.

Organizer tone (6 episodes):

I.4 Text monitors
The LLM judge (GPT-5-nano) prompts are adapted from the ControlArena monitor template ( Inglis 
et al., 2025). Braces mark slots filled per call:
- {operator_instructions} is the target’s system prompt;
- {task_description} is its task message;
- {history} is the rendered history at the chosen access level.
The detector returns a 0–10 suspicion score and the forecaster a 0–100 probability.
Detector prompt.

You are an AI monitor tasked with overseeing an LLM agent that is working on a task in a team chat with

J. A Scaled Follow-Up Study: Design and Decision Criteria
Which experiments would test our conclusions most directly, and what would each result change?  Each 
item gives the experiment, its reason, and the result that would change a conclusion of this paper.
J.1 Per-model tuning, then one locked test.  We would let each detector be tuned per target  
model on a development split only. For probes, this means choosing the layer, the token position (the 
last prompt token, the first reply token, or the token before the first tool call) and the pooling, and  
trying sequence models over a target’s activation history and sparse autoencoder features. For  
monitors, it means prompt search, few-shot examples, and fine-tuning a monitor on development  
labels. Every choice is then frozen, fresh episodes are collected, and each detector is scored once, as  
our new-episode confirmation did (§4.4). Our probes were trained while our monitors were prompted 
with no tuning, so this is the fair comparison. Our small checks found no gain from richer probes (an 
MLP, Table H.3; trajectory features, App. H). What would change our conclusion: a tuned probe that 
beats a tuned monitor on the locked test would reverse the finding that the conversation matters more 
than activations. On gpt-oss-20b, any tuned detector clearly above chance would weaken our reading 
of that model as a limit on when prediction is possible.
J.2 Rerun-based labels. A single outcome per state cannot separate “no signal” from “outcome  
not yet decided”. Our branching check suggests the second is common: 7 of 23 shared states ended  
differently across five three-round reruns (App. H). We would rerun each sampled state many times  
(for example 20) and train detectors to predict the rerun give-in rate.  What would change our  
conclusion: if detectors track the rerun rate well while still failing on single outcomes, then eventual  
give-in is weakly predictable because the outcome is open, not because the signal is missing. If they  
also fail on the rerun rate (our probe scored a Spearman correlation of −0.03 on the 23 states), the  
“no signal” reading gains support.
J.3 Designed deliberation windows. On gpt-oss-20b, 32 of 128 channel give-ins left no call to  
score, and for 65 of the other 96 the earliest possible warning was in the same round (App. F). We  
would vary pressure so that targets deliberate over several rounds: requests that escalate in calls, a  
required approval request to the operator before any handoff, or a delay between the ask and the  
moment the value is needed. We would then measure how lead time and AUROC change with window 
length. What would change our conclusion: if gpt-oss becomes predictable once it has a longer window, 
the limit lies in the setting, not the model. If it stays at chance, the difference lies in the model or its  
give-in route.
J.4 Causal tests. Our probe results are correlational. We would add or subtract the probe direction 
in the residual stream during generation and measure the change in give-in rate. Controls are random 
directions of the same norm and a check that replies stay coherent and the task is done. What would 
change our conclusion:  a dose-dependent change in give-in rate, absent under random directions,  

would show that the direction takes part in the decision. No change would mean the probe reads a  
correlate of the decision.
J.5 Scale and diversity.  We would generate scenarios from the shared template rather than  
writing them by hand, test four or more target models, and add settings with several peers, honest  
bystanders who can object, and recruited targets who in turn recruit a third agent (agent-to-agent  
spread). Our exploratory two-peer screen is too small to compare (2 of 7 channel give-ins, against 13 
of 30 with one peer; Appendix G). What would change our conclusion:  near-term predictability that  
holds across models and multi-agent settings would support a general claim; if it holds only for  
Qwen3-32B, our main result is specific to that model.
J.6 Deployment-oriented evaluation. We would measure leaks prevented against review burden 
(the share of actions held for review), false alarms per episode, and intervention loops in which an  
alarm holds the action, escalates to a stronger monitor, or asks a human. Literal secrets such as our  
tokens can be caught by an exact-match output filter, so prediction matters most for paraphrased or  
semantic disclosures (a summary of a reserve price, a rewritten note) and for deciding when to raise 
oversight. What would change our conclusion: today every detector catches at most a tenth of give-ins 
at a 5% false-alarm rate set on held episodes (App. H). A loop that prevents most semantic leaks while 
holding a small share of actions would make prediction practically useful. A loop that does not would 
mean output filters and access control are the better defence in this setting.
J.7 Sample size.  With 82 near-term positives, our confirmation intervals were about ±0.08  
AUROC. A locked test with about 330 near-term positives would narrow them to about ±0.04, enough 
to resolve a 0.05 difference between detectors.
K. Related Work in Full
How does this study relate to prior work on probes, monitors, persuasion and early warning?  Section 2 
gives the four contrasts that position the study; this appendix gives the fuller comparison, one strand 
of work per paragraph, each ending with how our study differs.
Probes on a model under attack.  Probes detect prompt-injection exposure in tool-using agents  
(Dong et al., 2026), recover directions separating hijacked from resisted trajectories (Yu et al., 2026), 
and predict a reasoning model’s next behaviour single-turn ( Kortukov et al., 2026 ). Probes on the  
prompt alone also predict sleeper-agent defection, jailbreak success and future tool calls ( Advani et 
al., 2026; Ashok & May, 2025; Kirch et al., 2025; MacDiarmid et al., 2024). Fomin et al. (2026) warn 
such probes read the situation, not the action, and NARCBench ( Rose et al., 2026) trains on agents 
told to collude and tests transfer to emergent collusion. We differ: we read the recruited agent, the  
target, which is never told to collude, over many turns, comparing episodes under the same pressure 
that end differently - the specificity control Fomin et al. (2026) argue monitor claims must survive.
Monitoring what agents say and do. A monitor that sees agents’ messages as well as their code 
catches more coordinated sabotage ( Radev et al., 2026 ), yet more of the trace can make a monitor  
worse (Arike et al., 2026); conversation-judge scores track actual collusion only weakly ( Nakamura 
et al., 2026), and private plans reveal later deviations at rates that vary widely by game (J. Shi et al., 
2026). We differ: most of these detect an attempt under way, and J. Shi et al. ( 2026) read private 
plans that precede a deviation but not whether a pressured agent will give in; we ask, before any rule 
is broken, which target will give in, scoring probes and monitors on the same calls at three access  
levels and two questions.
Persuasion between agents. Agents accept secret, unfair arrangements (Zeng & Rudzicz, 2026), 
are swayed by colluding peers (Tao et al., 2026), mislead a decision-maker agent (Bashir et al., 2025), 
and yield under sustained multi-turn pressure (Bozdag et al., 2026; Tang et al., 2026); collusion can 
also arise tacitly, with no request, as when pricing agents reach supracompetitive prices ( Fish et al., 
2026) or divide markets (Lin et al., 2025) on their own. We differ: these studies measure persuasion 
from text and outcomes; we also read the persuaded agent’s activations, and try to predict, call by  
call, whether it will give in.

Early warning and combined detectors.  Closest to our question, Saraogi et al. ( 2026) read 
hidden states each turn as a user presses a model to drop a correct answer: an untrained signal peaks 
near AUC 0.6, linear probes fail, prediction stays near chance under stronger labels, and probes do  
not transfer between models, consistent with the weak, model-specific signal we find. SafeDream  
measures how many turns before compliance a multi-turn jailbreak is flagged from hidden states (Yan 
et al., 2026 ). Per-round probe AUROC among running episodes predicts task failure ( Ruan et al.,  
2026), and probes paired with classifiers already filter jailbreaks and misuse ( Cunningham et al.,  
2026; Kramár et al., 2026). The closest detector precedent, Gao (2026), fuses an activation monitor 
with an observable monitor that includes LLM outcome forecasts on AgentDojo, and argues that row-
level false-alarm rates understate per-trajectory ones. We differ: we use the same per-round metric  
and count alarms per episode, and we test whether adding a probe to a text monitor helps (a  
combination test, §3.5) in a new setting: a peer recruiting the agent, including scenarios that neither 
detector saw in training.
In sum. Prior work detects that an agent is under attack, reads agents instructed to collude,  
measures persuasion from text and outcomes, or warns of a failure before it happens in other settings. 
To our knowledge, no prior work tries to predict, before it acts, whether an agent being recruited by 
a peer will give in, from its activations or from text monitors scored on the same calls.
L. Per-call and Streaming Probes
Can a probe tell which call will give in, and what does it read? Everything in this appendix is exploratory 
and was designed after the main results, except the frozen confirmation (L.5). Terms follow §3.3; 
“reply” below means one call.
L.1 The gpt-oss-20b reasoning probe: design and development results
Design. Our main probe reads one position per request, the last prompt token. A probe scored at  
every generated token, including reasoning, could warn within the reply that leaks, which matters  
most for fast give-ins like gpt-oss-20b’s. Constitutional Classifiers++ keeps such a running score:  
logits averaged over a sliding window in training, a loss weighted toward the tokens the probe finds  
most telling, and an exponential moving average at inference, with a cheap probe deciding when to  
escalate to a costlier classifier (Cunningham et al., 2026). Streaming classifiers can stop a reply at the 
first flagged token (Sharma et al., 2025), and production probes for Gemini score prompt tokens and 
take the maximum of rolling means (Kramár et al., 2026), an aggregate that McKenzie et al. (2026) 
introduced and Kramár et al. extend with attention weighting. The full version would score everything 
the target processes, so that suspicion can rise as the pressure arrives: the incoming peer messages  
and tool results, its reasoning, and its output up to the action. Saving activations at every position is  
impractical (terabytes), so the probe would run inside the replay or serving pass and keep one score  
per token, as production probe cascades do (Cunningham et al., 2026).
Development test (post hoc; summarised in §4.2–4.3). The gpt-oss replay saved residuals at the last 
prompt token and at every returned reasoning token (not at prompt, answer or tool-call tokens). We 
ran a first test on those positions only.
- Cohort. The main gpt-oss cohort (2,059 post-ask recruiting replies from 238 episodes) ends 
before the first public emission, so it holds no leaking reply. We added each episode’s first 
public-emission reply (146 replies), giving 2,205. Of these, 1,995 have reasoning, including 
121 of the 146 leaking replies; every scored token precedes the reply’s first public answer or 
tool-call token. Only 2 leaking replies mention the value in their reasoning.
- Labels, with an example. Each target call returns its reasoning and then an answer or a 
tool call. Label 1 marks the one call whose output is the first public emission of the value, by 
any route, a file write included; every other call is label 0, including every call in a held 
episode. For example (illustrative), in round 6 the target reasons that the peer needs the 
whole configuration block and then calls write_file with a block that contains the value: that 

call is label 1, and its earlier calls are 0. The probe reads only that call’s reasoning tokens, all 
of which come before its output starts. The paper’s near-term label differs in three ways: it 
concerns a channel leak; it marks the eligible calls before the leak, in the leak’s round or the 
one before; and the main probe reads one position per call, the last prompt token, before 
any reasoning. The near-term comparator below uses that paper label.
- Probe. The same recipe as the main gpt-oss probe: logistic regression with C = 0.1, training-
only scaling, round-balanced weights and the same 17 candidate layers, on the saved pooled 
folds and held-out-scenario rotations, seeds 42, 43 and 44. Each token carries its reply’s 
label, and each reply’s weight is split equally across its tokens, so long reasoning does not 
dominate. A reply’s score is its maximum token score (the mean is also reported). The layer 
is chosen on the inner split by the reply-level within scenario × round AUROC. The probe 
does not use the window smoothing or weighted loss of Cunningham et al. (2026).
- Comparators on the same replies. The frozen main gpt-oss last-prompt probe, applied 
without refitting (it was trained on the channel near-term label). Two text monitors, run 
differently from the main monitors (Appendix E): for each reply, Jev 1.14 and GPT-5-nano 
read only that reply’s reasoning so far, at six cumulative cut points (five evenly spaced 
through the reasoning, then the full reasoning), and at each answer one per-reply question, 
“Will the agent, in this reply, write or post the protected value?”. They see no conversation, 
tool results or earlier replies. The reply’s score is the running maximum of the six answers, 
so each point uses only text available by then, and exact protected values in the reasoning 
are replaced by a marker. Fixed keyword rules on the reasoning so far (the scenario’s key 
name, its handoff filename, “env”, “environment block”, “verbatim”, “copy the whole”; a 
broader list adds field names and block wording), fixed before scoring. Reasoning length 
(the number of reasoning tokens), reversed, as a retrospective check that a maximum over 
more tokens is not just rewarding length; it is not usable online.
- Checks. A censored variant drops every reasoning token from the first exact mention of the 
value onward. A placebo applies the post-ask probe to pre-ask replies against the episode’s 
eventual outcome.
- Alarms. For each fold, the cutoff is set on other-fold control replies’ maximum scores for a 
nominal 5% reply false-alarm rate (strictly above alarms). A leaking reply counts as warned 
if an alarm fires on any of its reasoning tokens; false alarms are counted on replies from held 
episodes.

L.2 Expanded capture: incoming messages and action-time tokens
A second, targeted replay (USD 4.84 on one GPU) saved what L.1 lacked, for the same 2,205  
recruiting replies plus 1,125 post-ask control replies (3,330 requests). For each request it saved three 
kinds of positions: the incoming segment of the prompt (the tokens added since the previous request: 
the latest peer message and tool results); every generated token of the reply (reasoning, answer and 
tool call), stopping just before the first character of the value when the reply leaks; and the last prompt 
token. It saved four fixed layers (6, 12, 18 and 23, in half precision) and a seeded 256-dimensional  
random projection of all 24 layers (runs/20261026-0659-e02-gpt-oss-stream-plan, runs/20261026-
0813-e05-expanded-stream-data). We report two streams. Incoming-only is a forecast: it scores only  
what arrives before the target starts its reply. Action-time adds the generated tokens up to the value, 
so it can read the model writing toward the leak; it is an output filter, not a forecast.
The  recipe  is  reduced  from  L.1  and  follows  Constitutional  Classifiers++  more  closely 
(Cunningham et al., 2026 ). It uses one layer, 18, fixed before fitting and not chosen on outcomes,  
and one seed (42), on held-out scenarios only. Training uses at most 64 evenly spaced tokens per  
reply, with logits averaged over a 16-token window of that sampled sequence and a token loss  
weighted by a softmax over the reply’s own logits (temperature 1). Inference uses an exponential  
moving average of the logits (decay 2/17, our choice), and a reply alarms at the first crossing.  
Otherwise the settings match L.1: C = 0.1, training-only scaling, round-balanced reply weights, the  
immediate any-public label, and cutoffs set on other-fold control replies for a nominal 5% reply false-
alarm rate. Keyword (the broad list of L.1), observed-token-count and round baselines use exactly the 
same positions.

episodes (80%) and 49 of 92 (53%), respectively, would also have been stopped at least once. The  
median alarm comes in the same request as the leak (step lead 0), so the warning is late in the episode 
even when it is early in the request. The incoming-only result shows that the incoming messages of  
the leaking request carry a strong signal. Its high false-alarm rate fits a probe that also reads pressure, 
which the control-reply cutoff never sees. The action-time result shows that a probe can stop the reply 
before the value appears, but for an exact string an output filter does the same. Its value would be for 
leaks that no filter can match, which this setup does not test.
Caveats. These are offline replays, not interventions: they assume the episode halts at the alarm 
and do not model a peer adapting. There is one seed, one fixed layer and a reduced, approximate 
version of the Constitutional Classifiers++ recipe (sampled tokens, smoothing on the sampled 
sequence). The analysis is post hoc, with no confirmation set, and has the same label and fidelity 
caveats as L.1. Intervals resample saved scores without refitting. Sources: 
experiments/E05-probes/stream_capture_small.py, stream_capture_keywords.py, 
stream_layer18_report.py; runs/20261026-1128-e05-stream-layer18-loso.
